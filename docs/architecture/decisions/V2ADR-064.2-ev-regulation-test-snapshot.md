# V2ADR-064.2 — Measured EV exclusion test and canonical snapshot

Status: Accepted for the explicitly authorized experimental test version,
2026-10-08. Live stability remains unverified.

Extends the observer slice V2ADR-064.1 after the user requested a working EV
protection test including HEMS. ADR-001–037 and the canonical ownership chain
remain leading. Energy Devices owns EV measurement and exclusion policy; it
selects no storage mode and issues no storage actuator commands. HEMS reads
physical RAW P1 plus the separate dated policy, never the EV meter directly.

With import-positive grid G, charge-positive actual storage B and EV E:
D = G - B; C = min(E, max(0, D)); R = G - C. Thus existing PV first supplies
physical house and EV, storage supports only eligible house demand, and genuine
PV surplus remains available for charging. Full EV subtraction is prohibited:
it could fabricate surplus and cause unintended grid charging.

The read-only Shelly-compatible API defaults to disabled. Disabled correction
returns fresh RAW exactly; enabled correction requires three consecutive usable
checks, reports at most 3 seconds old and at most 2 seconds apart. Missing or
stale feedback yields HTTP 503, not zero. Source freshness requires explicit
last_reported, power units and finite values. A derived template's unchanged
value is not evidence of stale physical data. The vendor wrapper therefore
checks the real CT report and embedded source timestamp, the selected CT mapping,
and the actual signed storage REST report, instead of the derived P1 timestamp.

The supplied wrapper replaces the confirmed @gielz automation, retaining its
original four NOM branches and all other actions. Its next normal 5-second
control tick blocks delegated NOM/slim charging/slim discharging on invalid
active feedback and invokes the vendor's existing zero-limit stop. Explicit fast
modes remain unchanged. Intentional disable is explicit; missing policy fails
closed. Actual scheduler and firmware timing require the practice test.

The separately published measured-external-load-support-policy:v1 snapshot has
source identity, revision, oldest report time, physical EV power and active
correction status. HEMS keeps physical observations intact, annotates identified
EV separately, removes identified EV only from the baseline/guard forecast view
when enabled, and adds current EV once for a bounded 15-minute continuation.
Unknown session duration is not invented. Every new snapshot replaces the
current contribution. EV grid import remains physical energy and full cost;
excluded energy is not eligible for battery assistance or a bridge shortfall.
Explicit fast-charge/export physics remain intact. The subset is preserved
through simulator, financial segmentation, comparison and commitment storage.

A start, stop, support-policy change or at least 100W change must persist across
observations for at least 30 seconds before entering the existing Runtime
Monitor as a household-state material transition. Revision/timestamp changes
and smaller noise do not trigger it. Detection is also bounded by the configured
HEMS polling interval (default 60 seconds), not promised to occur at exactly 30s.
Runtime Monitor → canonical MEP → Evaluation → Plan Builder remains the only
planning route. Legitimate SOC repair and the existing 100% objective remain.

Rollback disables both correction and HEMS policy, or restores the backed-up
CT REST resource and original vendor automation. All new options default off.
This release excludes advance session scheduling, smartplug actuation, charger
ownership changes, and a claimed proof of live stability.
