## Decisions

### Energy Profile Model

User Rules and Energy Profiles remain separate Core concepts.

A User Rule defines when, under which conditions and which action is executed. In Expert mode it may optionally contain a user-declared Planning Hint describing expected power, duration and energy.

Learning may evolve this into a Managed Energy Profile, but may never modify the IF/AND/OR/THEN logic or the external action target.

External Home Assistant automations and Homey flows remain black boxes. PicoT only triggers explicitly selected actions and never assumes their internal energy behaviour.

### Dual User Input Model

Where useful, PicoT offers:

- Simple mode for guided visual configuration;
- Expert mode for more precise and expressive configuration.

Both modes produce the same validated internal model. Expert mode never receives additional authority and cannot bypass Safety, hard constraints, validation, conflict handling or the Execution Pipeline.

### Layered Diagnostic Isolation

Diagnosis is non-destructive and proceeds per layer using temporary fallbacks.

Examples include bypassing User Rules, Expert configuration, Planning Hints, learned Energy Profiles, external actions or advanced Planner optimisation.

Original configuration remains unchanged and is restored after diagnosis. Baseline functionality and essential source data remain available.

### Progressive Complexity

The default PicoT experience remains simple. Additional complexity is shown only after explicit opt-in.

New functionality should extend existing Core models and reuse the same Planner, Explainability, Diagnostics and Execution Pipeline instead of creating parallel systems.
