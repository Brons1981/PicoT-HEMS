## Live Home Assistant deployment

PicoT HEMS was installed as a custom Home Assistant OS add-on on the dedicated NUC.

The live chain is:

```text
Nordpool price entity
→ Price Driven Strategy
→ deterministic mode decision
→ Home Assistant input_select
→ @gielz Zendure integration
→ Zendure battery
```

The add-on uses the Home Assistant Supervisor API and runs inside the Home Assistant environment. Development remains on the Windows PC, while stable versions are installed incrementally on the NUC.

## Price-driven strategy validation

The first live strategy selects one deterministic cheapest contiguous price window of 24 quarter-hour points, equal to six hours.

A live window of `10:30–16:30` was selected and PicoT correctly dispatched:

```text
Alleen slim ontladen
→ Nul op de meter
```

Subsequent runs returned:

```text
skipped_already_active
```

This confirmed that PicoT does not repeatedly send the same Home Assistant command.

### Critical sliding-window defect

The first implementation recalculated only over remaining future points. This caused the selected window to slide forward every quarter hour and could have prevented PicoT from leaving `Nul op de meter`.

The defect was fixed by preserving the complete daily price forecast for daily window selection. The active window now remains stable until its planned end.

### Local time

Runtime timestamps originally used UTC. The add-on now uses `Europe/Amsterdam` for planner evaluation and decision logs.

### Add-on build cache

Home Assistant initially reused an old Python installation layer while showing a newer add-on version. The Docker build was changed so add-on version changes invalidate the package-install layer.

## P1 and Shelly grid-power integration

PicoT first consumed the existing Shelly Pro 3EM Home Assistant sensor and was then switched to the already available one-second REST sensor:

```text
sensor.ct_shelly_pro_3em_api
```

The source is backed by a local Shelly REST endpoint. The concrete private-LAN address is intentionally omitted from the public repository.

The adapter normalises grid power as:

- positive = grid import;
- negative = grid export.

PicoT exposes:

- `grid_power_w`;
- `grid_import_w`;
- `grid_export_w`;
- `grid_direction`;
- source entity;
- source status;
- measurement timestamp.

The first live observation confirmed correct export interpretation at approximately 2.8 kW export.

P1/Shelly values are currently observational only and do not yet change the price strategy.

## Separated runtime data streams

The original single 60-second loop was separated into:

```text
Planner loop
→ every 60 seconds
→ reads price data
→ evaluates strategy
→ dispatches only when required

Telemetry loop
→ every 5 seconds
→ reads Shelly/P1 grid power
→ updates dashboard entities
→ does not re-run planning
→ does not dispatch
```

This creates the first practical separation between planning and live telemetry without introducing a new architectural layer.

The entities include relevant attributes such as strategy, reason, selected window, planner timestamp, telemetry timestamp, source entity and source status.

## PEP-UI-001 — PicoT Explainable Energy Cockpit

PEP-UI-001 was accepted as the long-term user-interface and data-architecture vision.

The cockpit is not intended to become a collection of unrelated cards. The final concept is one coherent Energy Scene with:

- the home at the centre;
- the grid mast;
- PV and a true seasonal sun arc;
- weather such as clouds and rain;
- battery and EV status;
- internet, price and forecast services;
- the PicoT T as the structural decision point;
- visible cause-and-effect explanations for planning decisions.

The cockpit may be modern, lively and visually rich. Informative and gently decorative animation is allowed, provided facts, forecasts and decoration remain distinguishishable and no non-existent physical state or flow is implied.

The governing principle is:

> Modern and visually rich, with truth and explainability as hard boundaries.

The cockpit must support both:

- a live perspective: what PicoT sees and does now;
- a historical perspective: what PicoT saw, decided and executed earlier.
