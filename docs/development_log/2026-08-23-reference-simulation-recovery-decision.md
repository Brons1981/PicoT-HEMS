# Development Log — 2026-08-23 — reference-simulation recovery decision

## Status of this decision

This log records the recovery decision accepted by the user on 2026-08-23 after a read-only inventory of the reverted dev.139 work.

It supplements the dev.140 recovery checkpoint in:

- `docs/development_log/2026-08-23-dev140-recovery-checkpoint.md`

This decision authorizes documentation of the recovery direction only. It does not yet authorize production-code changes, restoration of reverted files, a release, or changes to live planning and execution.

## Accepted objective

PicoT will build one independent full-day reference-simulation route alongside the current dev.140 pipeline.

The new route must:

1. start from the same immutable Planning Input as the current pipeline;
2. simulate the complete physical household energy path per canonical interval;
3. include PV, household demand, battery, grid, conversion losses and energy-contract semantics from the start;
4. generate its own hypothetical variants from that simulation basis;
5. evaluate only physically complete variants;
6. remain fully observer-only during validation;
7. expose its result next to the untouched current PicoT result;
8. be eligible to replace the current strategy only after practical evidence shows better and sufficiently stable outcomes.

The simulation may not depend on candidates, Evaluation results, commitments or plans generated by the current pipeline. Those current results are comparison evidence only.

## Why grid and finance belong in the simulation foundation

The grid- and finance-related work was intentionally brought forward.

The purpose was to avoid building a PV-only simulation that would later have to be opened and redesigned when grid charging, dynamic prices or market actions were added. That choice remains correct.

The problem was not the inclusion of grid and finance. The problem was that later slices connected these capabilities to the current Candidate Engine, canonical Evaluation and Execution path. That made the new result dependent on and capable of influencing the strategy it was intended to test independently.

The recovery must therefore preserve reusable physical and financial domain knowledge while rejecting the old-pipeline integration direction.

## Accepted architecture boundary

The current dev.140 pipeline remains authoritative and unchanged:

```text
shared Planning Input
├── current dev.140 pipeline -> active PicoT result
└── independent daily simulation
    ├── lower / central / upper physical baseline trajectories
    ├── independently generated hypothetical variants
    ├── identical physical interval simulation for every variant
    ├── completeness gate
    └── observer-only Evaluation -> hypothetical result

active PicoT result + hypothetical result -> comparison-only dashboard
```

The independent route may read the same captured input facts, but it may not consume the current pipeline's:

- Candidate Set;
- Candidate outcomes;
- Evaluation winner;
- Commitment;
- Execution Plan;
- primitive request;
- adapter translation;
- dispatch result.

## Required first vertical slice

The first production-code slice must implement one complete independent daily baseline simulation. It must not yet rebuild the Candidate Engine or activate grid charging.

For each canonical interval and for lower, central and upper PV scenarios it must expose:

- timestamp and interval duration;
- household demand;
- usable PV;
- PV to household;
- PV to battery;
- PV to grid or curtailment;
- battery to household;
- grid to household;
- grid to battery, initially zero for the physical NOM baseline;
- charge and discharge loss;
- battery energy at interval start and end;
- applicable source and destination policy;
- interval confidence and evidence;
- first interval in which the battery reaches its target;
- remaining reserve until the next charging opportunity;
- complete physical ledger;
- financial settlement over that exact ledger.

### Core physical invariant

For every simulated mode and every interval, the simulator must apply the energy flow that the delegated mode would physically cause.

For NOM/PV-surplus charging this means that available net PV surplus is taken immediately, subject only to:

- household demand first;
- remaining storage capacity;
- target energy;
- conversion efficiency;
- proven capability bounds.

The required energy may not be distributed artificially over the complete available PV window.

## Mandatory incident regression

The observed plan for 11:30–16:00 is a permanent acceptance case.

Known facts from the incident:

- expected battery energy at charge start: approximately 5.746 kWh;
- required addition: approximately 2.414 kWh;
- expected net PV surplus across the displayed window: approximately 7.584 kWh;
- the same forecast supplied approximately 2.684 kWh net surplus during the first three half-hour intervals;
- the old Candidate simulation spread the required energy until 16:00 instead of reaching the target around 13:00.

The independent simulator must calculate the physical target-reaching time from interval flows. It must not inherit the displayed technical availability window as the required charging duration.

## Later variant sequence

After the baseline slice is accepted:

1. generate PV-only variants independently;
2. simulate every variant through the same physical engine;
3. add bounded grid-requirement variants without changing the engine;
4. add financial settlement to every complete ledger;
5. reject incomplete or inconsistent variants through a completeness gate;
6. rank only admitted complete variants in a new observer-only Evaluation;
7. retain exact ties without a hidden tie-break;
8. add dynamic market actions only as complete linked cycles with all energy and financial consequences represented.

Commitment and live execution remain outside this sequence until observer acceptance is complete.

## Dashboard comparison acceptance

The observer release must show both results directly next to each other:

- **Active plan:** untouched result from the current dev.140 pipeline.
- **Observer variant:** hypothetical result from the independent daily simulation.

The observer variant must use one clearly different and consistent colour in text, border and any graph line. The chosen colour must not be confused with existing green success, red failure or established energy-source colours.

Both sides must expose at least:

- selected plan or action;
- charging window;
- required charging duration;
- expected battery energy at start;
- required energy addition;
- PV contribution;
- grid contribution;
- target-reaching time;
- reserve at the next charging opportunity;
- financial result;
- concise decision reason.

When results differ, the dashboard must highlight the deciding differences, for example:

- shorter or longer window;
- different target-reaching time;
- changed grid import;
- financial difference;
- different reserve.

The user must not need to inspect a large technical projection to understand which result each strategy produced and why.

## Accepted 48-hour observer trial

After implementation and verification, the independent route will run alongside the current pipeline for at least 48 hours.

During this trial:

- dev.140 remains the only authoritative planning and execution route;
- the new route cannot change candidates, Evaluation, commitments, modes or dispatch;
- both results are captured for every comparable planning run;
- plan changes and unchanged decisions remain historically inspectable.

The trial will compare:

- selected window and duration;
- expected versus actual battery state;
- target-reaching time;
- PV, household, battery and grid allocation;
- reserve until the next charging opportunity;
- financial outcome;
- response to updated measurements;
- full reason for a plan change or continuation.

## Manual-discharge stress test

The 48-hour trial includes an intentional unexpected manual battery discharge initiated by the user.

The test must remain above the configured safe minimum reserve. It is a planner-disturbance test, not a battery-safety test.

At the first valid Planning Input after the intervention, the independent route must:

1. recognize the newly measured lower battery energy;
2. mark the prior projection as superseded or stale;
3. restart from the new measured physical state;
4. recalculate the remaining horizon;
5. reassess PV-only feasibility;
6. include a bounded grid variant only when physically and contractually required;
7. explain every hypothetical plan change;
8. never continue from the old predicted battery state.

The current dev.140 pipeline remains untouched, allowing its reaction and the independent simulator's reaction to be compared directly.

### Stress-test invariant

An unexpected storage-state change must cause the next simulation to start from the latest proven physical state, never from the previous simulated state.

## Replacement decision after observation

The current strategy will not be replaced merely because the new code passes tests.

After at least 48 hours, replacement may be considered only when the accumulated evidence shows that the new route:

- produces physically conserved interval paths;
- responds correctly to unexpected state changes;
- avoids artificial long charging windows;
- provides stable but responsive planning;
- explains every material difference;
- produces demonstrably better physical and/or financial outcomes;
- passes the week's incident replays as a permanent acceptance set;
- remains operationally safe and fail-closed.

Any promotion from observer-only to authoritative planning requires a new explicit user decision and a separately reviewed implementation plan.

## Implemented outcome-assessment contract

The observer comparison now retains one persistent dossier per shared Planning
Input snapshot. Each dossier freezes the canonical decision and the independent
daily intent schedule before measurements can change. It then accumulates the
same measured PV, household, grid-import, grid-export, battery-charge,
battery-discharge and storage-energy evidence for both alternatives.

At the end of the daily horizon both intent schedules are replayed from the
same measured initial storage state, with the configured conversion efficiency,
physical power limits and the same versioned import/export tariff schedule.
Reserve, target reach, energy allocation and financial result are compared only
when every required measured series and every tariff interval has complete
coverage. Missing coverage produces `insufficient_data` and never a winner.

The append-only closed history and restart-safe open state are included in the
diagnostic export. The dashboard exposes the latest 48 hours and provides an
explicit manual-discharge marker. Marking a stress intervention supersedes the
prior projection for disturbance analysis; the next snapshot records that both
planners restarted from the newest measured storage state and did not reuse a
simulated state.

This assessment path remains observer-only. It has no selection, Commitment,
Execution Plan, primitive, adapter or dispatch authority and cannot replace the
canonical strategy without the separate replacement decision defined above.
