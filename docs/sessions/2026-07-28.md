# PicoT HEMS Session — 2026-07-28

## Goal
Refine capability management decisions and formalize the PicoT development workflow.

## Discussed

- Persistent capability mappings.
- The distinction between temporary unavailability and invalidity.
- Capability-scoped rediscovery.
- Multiple grid measurement sources.
- HomeWizard P1 as primary meter and a CT meter as an optional realtime power source.
- User-controlled source changes.
- Scope discipline for v0.1.
- Full repository and context synchronization at the start of each session.
- A short written report at the end of each session.

## Decisions

- A validated capability mapping remains active until objectively invalid.
- `TEMPORARILY_UNAVAILABLE` does not trigger replacement or rediscovery.
- Rediscovery is performed per capability.
- Discovery is not a continuous runtime mechanism.
- PicoT may propose alternative sources but may not silently switch them.
- Primary P1 and realtime power are separate source roles.
- GitHub is the source of truth.
- Architecture documents and ADRs are authoritative over chat history.
- Stored ideas are not accepted architecture until explicitly approved.
- Development follows: architecture future-proof, implementation minimal.
- Every session begins with `PicoT Start-of-Session (Full Sync)`.
- Every session ends with `PicoT End-of-Session` and a short report.
